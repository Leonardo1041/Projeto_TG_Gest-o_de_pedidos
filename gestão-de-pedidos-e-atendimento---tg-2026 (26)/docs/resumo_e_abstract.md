## RESUMO

O setor de alimentação fora do lar enfrenta desafios operacionais recorrentes relacionados ao atendimento presencial em salão, onde métodos manuais com comandas de papel ou sistemas descentralizados resultam em falhas de comunicação entre salão e cozinha, perda de pedidos, erros na cobrança e inconsistências no controle de ocupação de mesas. Este Trabalho de Graduação apresenta o projeto, a arquitetura e o desenvolvimento de um sistema web full-stack voltado especificamente para o fluxo operacional de salão em restaurantes e estabelecimentos gastronômicos. A solução integra três módulos especializados com controle de acesso baseado em papéis (RBAC): o módulo do garçom, para lançamento de comandas vinculadas a mesas físicas e acompanhamento dos pratos; o módulo da cozinha, estruturado como um *Kitchen Display System* (KDS) em modelo Kanban para gestão das etapas de preparação e expedição; e o módulo administrativo, destinado ao gerenciamento de colaboradores, cardápio e mesas pelo gerente. No aspecto arquitetural, a aplicação adota uma Single Page Application (SPA) em React 19, TypeScript e Tailwind CSS no cliente, combinada a uma camada de serviços em Node.js e Express com banco de dados relacional SQLite 3 em modo *Write-Ahead Logging* (WAL) e integridade referencial ativa. A segurança é garantida por meio de senhas criptografadas em hash bcrypt e autenticação *stateless* com tokens JSON Web Token (JWT), enquanto a máquina de estados finita assegura a transição consistente dos pedidos (Recebido, Em Preparação, Pronto, Entregue e Cancelado). Para validar a solução, realizou-se a suíte completa de testes de aceitação (Quadro 7), na qual foram executados oito cenários cobrindo cadastros, recálculo de preços no backend, validações de mesa ocupada, fluxo KDS, cancelamentos, controle de permissões, persistência em disco e a rota atômica de encerramento de atendimento (`POST /api/orders/:id/close`). Os resultados confirmaram 8 cenários aprovados e 0 reprovados, sem a ocorrência de nenhuma falha, comprovando que os principais fluxos operacionais previstos foram executados com sucesso no ambiente avaliado e que os dados mantêm a integridade e persistência física no arquivo SQLite. A avaliação de usabilidade em campo com usuários reais e a mensuração de impactos na velocidade do atendimento permanecem como trabalhos futuros.

**Palavras-chave:** Sistema de Gestão de Restaurantes. Comanda Eletrônica. Kitchen Display System (KDS). SQLite Relacional. Controle de Acesso Baseado em Papéis (RBAC).

## ABSTRACT

The food service industry frequently faces operational bottlenecks in on-premises dining, where legacy manual practices based on paper tickets or disconnected systems lead to communication errors between floor staff and the kitchen, order loss, billing inaccuracies, and table status inconsistencies. This Undergraduate Thesis presents the design, architecture, and implementation of a full-stack web application tailored specifically to the operational workflow of sit-down restaurants and food service establishments. The platform integrates three role-specialized modules through Role-Based Access Control (RBAC): the waiter module, for placing electronic orders strictly tied to physical tables and tracking preparation in real time; the kitchen module, designed as a Kanban-based Kitchen Display System (KDS) to streamline cooking and expedition; and the management dashboard, dedicated to staff administration, menu cataloging, and table layout maintenance. Architecturally, the solution employs a Single Page Application (SPA) using React 19, TypeScript, and Tailwind CSS on the frontend, coupled with a Node.js and Express backend backed by a relational SQLite 3 database operating with Write-Ahead Logging (WAL) and enforced foreign key constraints. Application security is reinforced through bcrypt password hashing and stateless JSON Web Token (JWT) authentication, while a finite state machine enforces strict operational order transitions (Received, In Preparation, Ready, Delivered, and Canceled). System validation was conducted through the official acceptance test specification (Table 7), comprising eight comprehensive scenarios encompassing user registration, server-side price recalculation, occupied table collision prevention, kitchen workflow progression, cancellation policies, access control restrictions, disk persistence, and attendance closure (`POST /api/orders/:id/close`). The empirical results confirmed 8 passed scenarios and 0 failures, registering complete operational success and demonstrating that key dining workflows and data integrity maintain physical persistence in the SQLite file in the evaluated environment. Usability evaluation with real users and quantitative performance measurements remain as future work.

**Keywords:** Restaurant Management System. Electronic Order Management. Kitchen Display System (KDS). Relational SQLite. Role-Based Access Control (RBAC).
